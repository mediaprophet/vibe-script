Implementation truth

A promise needs a boundary.

VibeScript’s language core is real and browser-checkable. Its larger creative environment depends on capability hosts. This map makes that distinction explicit so a polished demo never becomes a false claim.

Three truths

Where a feature lives matters.

The browser page can parse, diagnose, and evaluate source through the WASM build. It cannot impersonate the Poet desktop or every native QualiaDB host capability.

RUNS NOW

Vibe 0.1 engine

Grammar, checker, diagnostics, projection, cells, effects, budgets, quantities, catalog leasing, animation kernels, presentation morphisms, bytecode, and the WASM evaluator are implemented engine behavior.

HOST-DEPENDENT

Capability execution

Graph commits, HID events, GPU/render surfaces, native acceleration, devices, sessions, and real data are deliberately host-owned. The source can describe them; a browser sandbox may not provide them.

PLANNED / UNBOUND

Product-scale toolchains

Several ambitious domains in the design set need new host APIs or bindings: scene editing, full audio/DAW tools, research workflows, advanced NLP, agent lifecycle tooling, and hypermedia authoring.

Design audit

What the design set says is still missing.

This is a condensed, dated view of the 21 August capability-gap audit. It assesses the broader Poet interface against QualiaDB—not a defect list for the 0.1 parser.

AreaCurrent positionWhat closes the gap
Core 0.1Implemented: language bindings, evaluation, diagnostics, transactions, cells, capability invocation, time, graph primitives, and effect classes.Keep conformance and browser WASM parity visible through executable fixtures.
Spatial / 3DRender GPU primitives, geometry, manifold operations, and animation kernels exist; a high-level semantic scene graph and inverse kinematics remain incomplete or unbound.Bind scene construction, node transforms, mesh/material assignment, lighting, capture, and IK to a host.
AudioThere is a spectral-first backend, but a traditional DAW layer—transport, synths, effects, MIDI, and articulated speech—is not a current Vibe surface.Expose spectral primitives first; build DAW abstractions only where the host requires them.
Agent / AISome DAG and NLP primitives exist, while planning, evaluation, tracing, model lifecycle, GraphRAG, coreference, and relation extraction are incomplete or need bindings.Publish versioned discovery, diagnostics, and a constrained agent/MCP contract before general execution.
HypermediaThe audit identifies image, video, 3D-editing, HbbTV, portal, world, DMX, and production work as a large future surface.Build capability registries and host integrations; do not represent these as browser features before they are real.
Rights & disclosureFail-closed capability checks and related governance pieces exist; the design calls for explicit disclosure manifests, session leases, redacted reports, and traceable deny/grant receipts.Implement these at the host/tool layer, not as a cosmetic access-control overlay.

Evidence: Vibe design capability-gap audit (2026-08-21), agent/MCP implementation specification (2026-08-22), and the engine source reviewed in QualiaDB. The audit is a planning snapshot; individual bindings may evolve after its date.

What this site can prove

Executable claims, not simulated ownership.

The capability atlas displays source from shipped fixtures and asks the bundled Vibe engine to diagnose it. The workbench can evaluate simple local programs and perform a bytecode round-trip. Those are direct browser proofs.

Why the Pages demo still cannot be Poet

A static GitHub Page has no authority over local data, HID hardware, graph state, GPU pipeline, credentials, or a desktop session. Treating a canvas animation as proof that those hosts are present would defeat Vibe’s own capability and disclosure model.
