Execution profiles

One language.
More than one runtime.

VibeScript can run directly in a browser, with deterministic local kernels for selected capabilities. A resource host extends the same source into live graph, device, security, timing, and compute environments when an application supplies those resources.

Check shipped fixturesOpen the browser workbench

Choose the right profile

Every result has a clear execution home.

The browser build is a useful Vibe runtime in its own right. Resource hosts add the parts that should belong to an application, machine, or approved environment.

BROWSER ENGINE

Author, check, and evaluate

WebAssembly provides parsing, checking, diagnostics, source projection, structural edits, reactive evaluation, budgets, quantities, and bytecode operations inside the page.

LOCAL KERNELS

Deterministic, in-process work

Animation presets, spring evaluation, and selected logic kernels run locally. The browser runner also carries in-memory graph and pulse state for compact, repeatable experiments.

RESOURCE HOST

Attach a live environment

A host implementation can connect the same language to real graph data, clocks, devices, credentials, compute, receipts, and application-specific capability handlers.

The public workbench uses the Vibe WebAssembly package with its built-in LocalHost. These are the concrete behaviours of that profile.

When an application attaches a host

Live resources remain available through the same language contract.

A native or application host implements only the bindings it can responsibly provide. Vibe reports an unavailable binding instead of silently substituting one.
